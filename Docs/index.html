Direct3D 11 · C++ Rendering

SpriteBatchDemo

엔진 없이 Win32와 Direct3D 11만으로 만든 2D 스프라이트 렌더러. 같은 장면을 개별 드로우(Naive)와 배치(Batched)로 실시간 전환하며, 드로우 콜 방식이 성능에 주는 영향을 숫자로 실측한다.

DirectX 11 C++17 / x64 무외부의존 AMD Radeon 780M (내장) github.com/AIMHYUK/SpriteBatchDemo

04기술 노트

정점 베이킹 — 단위 사각형+상수버퍼 → 픽셀 좌표

MiniD3D11Renderer는 단위 사각형(0~1) 하나에 위치를 상수 버퍼로 넘겼다. 스프라이트 하나엔 깔끔하지만, 위치가 CB에 있어 개수만큼 CB를 바꿔 그려야 한다 = 배칭 불가. 그래서 각 스프라이트의 네 꼭짓점을 픽셀 좌표로 CPU에서 미리 구워, 모두 같은 좌표계에 두고 한 버퍼로 묶었다.

MiniD3D11Renderer: 단위 사각형 1개 + 상수버퍼(위치) → 스프라이트 1개 SpriteBatchDemo: 픽셀 좌표 N×4개(버퍼에 구움) → 스프라이트 N개 (배칭 가능)

두 경로 — Naive vs Batched

Naive는 실무의 순진한 경로: 스프라이트마다 정점 4개를 동적 버퍼에 Map(WRITE_DISCARD)로 올리고 → 그린다, 를 N번. Batched는 IMMUTABLE 버퍼에 전부 구워 DrawIndexed(N*6) 한 번.

처음엔 Naive를 "가장 싸게"(오프셋만 바꿔 그리기) 만들었더니 격차가 1.35배뿐이었다. 드로우 콜당 ~16ns라 GPU 렌더 비용에 묻힌 것. 실무형 per-object 경로로 바꾸고서야 의미 있는 차이가 났다.

VSync 함정 — Present(0,0)만으론 안 풀린다

SyncInterval을 0으로 줘도 두 모드가 똑같이 16.677ms(정확히 60FPS)로 나왔다. 원인은 플립 모델 + 창모드 — DWM(윈도우 합성기)이 주사율로 다시 묶는다. 진짜로 풀려면 tearing을 켜야 한다: IDXGIFactory5로 지원 확인 → 스왑체인/ResizeBuffers에 ALLOW_TEARING 플래그 → Present(0, DXGI_PRESENT_ALLOW_TEARING). 이걸 넣고서야 프레임 시간이 갈라졌다.

텍스처 아틀라스 (코드 생성)

도형 4종(원·링·다이아몬드·+)을 256×256 한 장에 코드로 그린다(외부 이미지·라이브러리 없음). 스프라이트마다 UV로 하나씩 뽑아 쓴다. 한 장에 모아둔 덕에 텍스처 바인딩을 스프라이트마다 바꿀 필요가 없어, SRV 한 번으로 2만 개를 배칭 한 번에 그린다 — 실제 엔진이 아틀라스로 state change를 줄이는 이유 그대로다. 알파 블렌딩으로 가장자리를 배경과 섞어 파티클처럼 보이게 했다.

① 정적 배칭 — 위치 고정 (원리 검증)

정점을 한 번 굽고(IMMUTABLE) 매 프레임 그리기만. Batched는 업로드가 아예 없어 극단적 격차.

② 동적 배칭 — 매 프레임 이동 (실제 게임 조건, 현재 빌드, 3모드)

스프라이트가 움직여 매 프레임 재업로드. Batched는 정점을 한 번에, Instanced는 인스턴스 N개(~1/3 데이터)만 올린다.

모드드로우 콜CPU 제출올리는 데이터FPS
Naive20,000~1.8 ms정점 N×4 (N번 쪼개)309
Batched1~0.3 ms정점 N×4 (한 번)434
Instanced1~0.14 ms인스턴스 N (한 번)463
  • Naive→Batched 약 5~8배, Batched→Instanced 약 2배(올리는 데이터 1/3), Naive→Instanced 약 13배
  • 정적(2,900배)은 배칭의 상한, 동적은 실전 이득. 핵심은 같다 — 렌더 스레드 CPU를 비운다
  • CPU측 비용이라 실행마다 흔들린다. 견고한 결론은 순서와 자릿수
심화 — 제출 시간을 Map()/memcpy로 쪼개보니: Batched의 Map()은 이동·정지 모두 0.001ms(안 기다림). WRITE_DISCARD가 VidMM rename으로 GPU 대기를 없앤 것. 제출 시간의 거의 전부는 memcpy(CPU 복사)였다 — 즉 이 지표는 드라이버/GPU가 아니라 CPU 비용. 추측하지 않고 쪼개서 측정해 확인했다.

06파일 구조

src/ main.cpp 진입점. 창과 렌더러를 연결하고 게임 루프를 돌린다. Window.* Win32 창 하나. D3D를 모른다. 크기 변경·키 입력은 콜백으로만. Renderer.* 디바이스·스왑체인·스프라이트 버퍼 소유, Naive/Batched로 한 프레임. FrameTimer.h QueryPerformanceCounter 기반 평균 FPS / 프레임 시간(ms). Common.* ComPtr 별칭, HRESULT 검사 매크로, exe 기준 경로 해석. shaders/ Sprite.vs.hlsl 픽셀 → NDC 변환, UV 전달. Sprite.ps.hlsl 아틀라스 샘플 × 정점 색, 알파 블렌딩.
